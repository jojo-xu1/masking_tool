# マスキングツール Constitution

## Core Principles

### I. 明示的な対象範囲と非対象範囲
本ツールは `.txt`, `.csv`, `.log`, `.docx`, `.xlsx`, `.pptx`, `.pdf` のみを処理対象とする。
フォルダ指定時は配下の対象ファイルすべてを処理し、対象外拡張子は変更せず
`skipped_unsupported` としてレポートへ記録しなければならない。第一版では画像内文字、
スキャン PDF、埋め込みオブジェクト、OCR を対象外とし、仕様・計画・テストでこの境界を
明示しなければならない。

### II. 検出結果に基づく不可逆置換
マスキング処理は機密情報検出結果ファイルの `検出語句` を `置換提案` に置換する方式を
唯一の基本契約とする。置換後の値は分類ラベル付きで、原文を復元できない値でなければ
ならない。実装は新たな検出推論を暗黙に追加してはならず、追加検出が必要な場合は
設定ファイルまたは仕様で明示された正規表現、個別指定、または ML/NER などの検出ソース
だけを使用しなければならない。ML/NER 検出は、対象言語、オン・オフ状態、利用不能時の
扱い、レポート上の判定理由、置換提案の再現性を仕様と計画で明示した場合に限り使用
できる。

### III. 出力の再現性と監査可能性
同一入力、同一設定、同一言語指定、同一検出結果では同一の置換結果とレポートを生成
しなければならない。置換済みファイルは `output` フォルダへ出力し、元ファイルを直接
上書きしてはならない。`機密情報検出結果.xlsx` は `No`, `検出語句`, `置換提案`,
`原文または前後の文脈`, `情報カテゴリ`, `リスクレベル`, `判定理由`, `推奨対応` を含み、
リスクレベルに応じた行色を適用しなければならない。

### IV. 設定駆動の多言語マスキング
マスク対象は設定ファイルで管理し、`正規表現で置換` と `個別指定した内容を置換` の
両方式をサポートしなければならない。一般的な機密情報の正規表現はオン・オフ可能な
既定ルールとして提供し、英語、日本語、中国語向けのデフォルト設定を用意しなければ
ならない。単一ファイル処理では処理開始前にファイルの言語指定を必須とし、未指定または
未対応言語は処理前に明確なエラーとして扱わなければならない。フォルダ処理では、仕様で
明示された場合に限り、ファイルごとの自動言語判定を使用できる。自動判定を使用する
機能は、判定不能時に対象ファイルを置換せず、理由をレポートへ記録しなければならない。

### V. Python 優先と安全な第一版
実装言語は Python とし、Office ファイル、テキスト型 PDF、テキストファイルを扱う処理は
失敗時に入力ファイルを破壊しない構造で実装しなければならない。第一版では安全性と
再現性を機能拡張より優先する。新しいファイル形式、OCR、画像処理、埋め込みオブジェクト
処理を追加する場合は、憲章改定または仕様内の明示的なスコープ変更を必要とする。

## 対象成果物とデータ契約

成果物は `機密情報検出結果.xlsx` と `output` フォルダ内の置換済みファイルとする。
レポートは処理済み、置換なし、対象外スキップ、失敗を区別できなければならない。
ファイル処理は原則として入力と同じ相対パス構造を `output` 配下へ再現し、同名衝突が
発生する場合は仕様で定めた決定的な命名規則に従わなければならない。

設定ファイルには少なくともルール種別または検出ソース種別、対象言語、オン・オフ状態、
情報カテゴリ、リスクレベル、置換提案生成または固定置換値を表現できる項目を持たせ
なければならない。ML/NER 検出を使う場合は、利用するモデルまたは検出器名、必須/任意の
扱い、利用不能時の処理方針を設定または計画で追跡できなければならない。
レポートと置換済みファイルの文字コード、改行、Office/PDF 固有の制約は、計画段階で
検証方針を定めなければならない。

## 開発ワークフローと品質ゲート

すべての仕様は、対象拡張子、非対象範囲、単一ファイル時の言語指定、フォルダ時の
言語判定方式、設定ファイル、出力先、レポート列、リスク色分け、エラー時の扱いを
明示しなければならない。追加検出ソースを導入する仕様は、検出方式、対象言語、オン・
オフ制御、衝突解決、利用不能時の扱い、監査方法を明示しなければならない。計画では
Python バージョン、使用ライブラリ、Office/PDF の処理方式、テスト対象サンプル、再現性
確認方法を記載しなければならない。

実装タスクには、テキストファイル、Office ファイル、テキスト型 PDF、フォルダ一括処理、
対象外拡張子、設定オン・オフ、単一ファイル時の言語未指定、フォルダ時の言語判定不能、
レポート生成、`output` 出力の検証を含める必要がある。マスキング結果、レポート内容、
スキップ記録、入力ファイル非破壊性は自動テストまたは明示的な検証手順で確認しなければ
ならない。

## Governance

この憲章は、マスキングツールの仕様、計画、タスク、実装判断に優先する。憲章と矛盾する
要求は、実装前に仕様または憲章を更新し、影響範囲と移行方針を記録しなければならない。

バージョンはセマンティックバージョニングに従う。対象範囲、置換契約、出力契約、
安全性原則を破る変更は MAJOR、原則または必須ゲートの追加は MINOR、文言修正や明確化は
PATCH とする。各 feature の計画時には Constitution Check を通過し、実装完了前に
再確認しなければならない。
